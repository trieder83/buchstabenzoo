# Building Letter Zoo for iOS

No Mac needed: the build runs on a GitHub macOS runner (`.github/workflows/ios.yml`), exactly like ABC Smash
(`../abcshooter/BUILD_IOS.md`). The app is the web game wrapped by **Capacitor 8** (`web/ios`, `web/capacitor.config.ts`) with the game
**bundled inside the app** (offline). Spec: `specs/40-tech/app-store.md`. Store texts: `store/appstore/`.

| What | Value |
|---|---|
| App name | Letter Zoo (German localisation: Buchstabenzoo) |
| Bundle ID | `ch.rcms.letterzoo` (ABC Smash: `app.abcshooter.ios`, Math Fighter: `com.mathfighter.app`: no common pattern; this one follows the rcms.ch domain) |
| SKU | `letterzoo-ios-001` |
| Team ID | `AZFUSL233G` (same Apple Developer account as ABC Smash / Math Fighter) |
| Scheme / project | `App` / `web/ios/App/App.xcodeproj` (generated by Capacitor, committed) |
| Version | `web/package.json` `version`; build number = GitHub run number |
| Price | Free, no IAP, Kids Category (recommended, Q-390) |

## USER CHECKLIST (in this order)

1. **Apple Developer Program**: already enrolled (team `AZFUSL233G`). Nothing to pay. The *Free Apps* agreement is active by default
   (App Store Connect -> Business); paid-app banking/tax is not needed for a free app.
2. **Register the bundle ID**: https://developer.apple.com/account/resources/identifiers/list -> `+` -> App IDs -> App -> description
   `Letter Zoo`, explicit `ch.rcms.letterzoo`, no capabilities.
3. **Provisioning profile**: https://developer.apple.com/account/resources/profiles/list -> `+` -> *App Store Connect* (distribution) ->
   App ID `ch.rcms.letterzoo` -> the existing **Apple Distribution** certificate (the one ABC Smash uses; do NOT create a third, the team
   is at Apple's limit) -> name it exactly `Letter Zoo App Store` -> download the `.mobileprovision`.
4. **GitHub secrets** (repository `trieder83/buchstabenzoo` -> Settings -> Secrets and variables -> Actions). Same names as ABC Smash;
   the values are the same *except* the profile:
   - `IOS_DIST_CERT_P12`, `IOS_DIST_CERT_PASSWORD`: the ABC Smash distribution certificate (`../abcshooter/.ios-signing/`, base64 of the
     `.p12` and its password; never paste them into chat or commit them).
   - `ASC_KEY_ID`, `ASC_ISSUER_ID`, `ASC_KEY_P8`: the App Store Connect API key (Users and Access -> Integrations -> App Store Connect API;
     the ABC Smash key `abcshooter-ci` with App Manager access works; `ASC_KEY_P8` = base64 of the `.p8`).
   - `IOS_PROVISIONING_PROFILE`: `base64 -w0 LetterZoo_AppStore.mobileprovision` of step 3.
   With the GitHub CLI, from a folder holding the files: `base64 -w0 file.p12 | gh secret set IOS_DIST_CERT_P12 -R trieder83/buchstabenzoo`
   and `gh secret set IOS_DIST_CERT_PASSWORD -R trieder83/buchstabenzoo` (prompts for the value).
5. **App record**: https://appstoreconnect.apple.com -> My Apps -> `+` New App: iOS, name **Letter Zoo** (if taken: see
   `store/appstore/README.md`), primary language **German**, bundle ID `ch.rcms.letterzoo`, SKU `letterzoo-ios-001`, full access.
   Apple Store ID of the new app goes into the `store/` docs and later into ABC Smash / Math Fighter if they should advertise it.
6. **Approve the icon** `web/ios/App/App/Assets.xcassets/AppIcon.appiconset/AppIcon-512@2x.png` (it is the PWA icon at 1024 px; make a nicer one by
   changing `tools/make_icons.py` and re-running it) and the cream launch image.
7. **Fill in the contact**: the privacy page still contains the placeholder for name, address and e-mail of the controller
   (`web/public/privacy.html`), and the support URL page needs a visible e-mail (Q-396). Deploy the web once so the privacy URL is live
   (`https://letterzoo.web.app/privacy.html`, alias `https://letterzoo.rcms.ch`).
8. **Push** to GitHub, then Actions -> *iOS build* -> *Run workflow* (upload on). After 5-15 min the build shows in App Store Connect ->
   TestFlight. Add yourself as **Internal Testing** tester, install with TestFlight on an iPhone and an iPad and run the manual
   checks PLAT-043.
9. **Store page** (App Store Connect -> the app -> iOS app version 1.0): add the localisations English (U.S.), English (U.K.), German and
   paste the files of `store/appstore/<locale>/` (name, subtitle, promotional text, description, keywords, support / marketing URL);
   copyright `2026 Thomas Rieder`; screenshots from `python3 tools/store/make_appstore_screenshots.py` (iPhone 6.9", iPad 13");
   App Privacy -> **Usage Data -> Product Interaction, purpose Analytics, Not Linked to You, not used for Tracking** (NOT "Data Not Collected": the anonymous first-party counters, `store/appstore/README.md`); Age Rating questionnaire all "None" (-> 4+); Kids Category with age band 6-8; category Games ->
   Educational; price Free; Availability: US, GB, DE, AT, CH; "Sign-in required": no; Notes for Review: `store/appstore/review_notes.txt`;
   Export compliance is answered by `ITSAppUsesNonExemptEncryption = false`; Content Rights: no third-party content; release:
   *Manually release this version*. Details: `store/appstore/README.md`.
10. Select the TestFlight build, **Add for Review -> Submit** (the owner submits; typically 24-48 h). Fix rejections by changing code or
    texts and running the workflow again (a new build number is automatic).

## Day to day

```bash
# local web check of the native variant (Linux)
cd web && npm run build:native && npx cap sync ios        # copies web/dist into web/ios/App/App/public (git-ignored)
# on a Mac only: npm run cap:open -> Xcode -> Run
```

**Version bump**: edit `web/package.json` `"version"` (also `MARKETING_VERSION` in `web/ios/App/App.xcodeproj` only matters for local Xcode
builds; the workflow passes both numbers), commit, push, run the workflow. **Unlike ABC Smash a web deploy does not update the app**:
the game is bundled, every change needs a new build and review.

## Native build differences (VITE_NATIVE=1)

- Google Analytics is fully off (no 📊 button, no welcome consent dialog, no `gtag` script, no Google Analytics request). The anonymous first-party counters (`web/src/counter.ts`, no identifiers) run in the native build too and send plain daily totals to our own Firestore (`firestore.googleapis.com`). The web build is unchanged.
- Posters: only the developer's own App Store pages via the native manifest (`boards-native/`), behind the parental gate; see
  `specs/40-tech/app-store.md` "Native posters" for the three code steps that are still to apply and the signing command
  (the production key stays offline). Until `NATIVE_ADS = true` the native build shows only placeholders and makes no ad request.
- `localStorage` (save, settings) lives in the app's own origin `capacitor://localhost`: no progress transfer from the web version.

## Troubleshooting (from ABC Smash)

| Issue | Solution |
|---|---|
| `No signing certificate "Apple Distribution" found` | The `.p12` was exported by OpenSSL 3 without `-legacy`; re-export it. |
| `No profile for team AZFUSL233G matching 'Letter Zoo App Store'` | Profile name differs from the one in `web/ios/ExportOptions.plist` / the Release configuration, or it was created for another certificate. |
| Upload rejected: built with an older SDK | The "Select Xcode" step needs an Xcode 26+ on the runner image. |
| Upload rejected: build number already used | Re-run (new run number). Never lower `version`. |
| White screen on the device | `.wasm` MIME in `capacitor://`: check the Safari Web Inspector console (Settings -> Safari -> Advanced -> Web Inspector); `wasm-bindgen` falls back to ArrayBuffer instantiation. |
| Optional Android | not set up; ABC Smash uses a Trusted Web Activity (bubblewrap) of its deployed site: `https://letterzoo.web.app` could be wrapped the same way later (needs the Play Console, 12 testers for 14 days for new personal accounts). |
